This page lists each threat the dashboard faces, the control in this repository that answers it, the test that covers the control, and the status of the row. It covers the server code in `src/server`, the engine in `engine/`, the dispatch Worker in `dispatch/` and the public contracts in `contracts/src`. Controls for features that are not built yet are listed at the end and are not claimed in the tables.

## How to Read the Rows

Every claim carries a tag.

- `read`: the source was read and the location is cited.
- `measured`: a spec under `tests/` covers the control, and it passes in the repository test run.
- `inferred`: it follows from the design, and nothing was run against it.

Every row closes to one verdict.

- `removed`: the attack path needs a component that does not exist. The row reopens when the component lands.
- `contained`: the flaw or foothold exists, and a named control limits what it reaches.
- `open`: the control is missing, unbuilt, not wired into production, or could not be established. A claim that could not be established counts as `open`.

A row names only controls that are in this repository. A fixed defect is described by what it was, and the test that proves the fix is listed in its row.

## Known Gaps

These gaps cut across the rows above.

- Key organisation and site restrictions are not stored or enforced.
- The facts loader has ports for suspensions, support standing and policy groups, and boot installs none of them. Each defaults to empty, so no organisation is suspended, no support grant applies, and no policy group applies (`src/server/services/facts.ts`).
- The Swagger page and the script policy have not been loaded in a browser.
- The DoH resolver has not been run against the real endpoint.
- The fleet-link command check needs the same change in every node that verifies commands. The contract version is not bumped.
- The rate limiter is per isolate, with placeholder rates.
- Revocation propagation and host removal through KV have no measurement.

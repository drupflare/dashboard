This page lists each threat the dashboard faces in Phase 1, the control that exists in the repository, the test that fails without it, and an honest status. It covers the code in `src/server`, `contracts/src` and `.github`. Controls the plan promises for later phases are listed at the end and are not claimed here.

## How to Read the Rows

Every claim carries a tag.

- `read`: the source file was read and the location is cited.
- `measured`: a test ran, and the spec is named.
- `inferred`: it follows from the design and nothing was run against it.

Every row closes to one verdict.

- `removed`: the attack path needs a component that does not exist.
- `contained`: the flaw or foothold exists and a named control limits what it reaches.
- `open`: the control is missing, unbuilt, untested, or could not be established. A claim that could not be established counts as `open`.

A row never names a control that is not in the repository. Where a test is listed, it is a spec file under `tests/`. `F1` to `F12` refer to the demonstrated defects in `tests/unit/security/findings.spec.ts`; each is an `it.fails` test, so the defect list is executable.

## What Phase 1 Does Not Cover

These controls are in the plan and are not built. Each stays `open` until its phase lands.

- Leases, `SITE_AUTH`, strict mode and the revocation tests ("Architecture", P2). Spike S13 supplies the measured propagation.
- The Gate and its assertion, redirect and cookie tests ("Environments and Access", P4).
- The abuse queue, the outbound Worker and per-call limits for customer Workers ("Security Threat Model", P2).
- Per-site resources, domain states, tombstone holds and the deleted-hostname test ("Operations and Planes" and "Managed Deploy and the v1.0.4 Config", P2).
- The cross-tenant live test and sealed previews ("Security Threat Model", P4).
- The shard-loss restore test and the lost-admin-access test ("Security Threat Model", P5).
- SSH import and archive extraction controls ("Security Threat Model", P3).
- Credential custody classes beyond the owner token, and the owner-assertion replacement of stored tokens ("Operations and Planes", P3).
- A `LIMITER` Durable Object, atomic code and idempotency stores, and the single-use records move out of KV (P2).

An estate is every Drupal site your institution runs. This walkthrough puts them in order, from a list of sites to the day each one moves.

## 1. Inventory

Start with a list of sites, their owners and their hosts. The migration assessment reads a server or a site and produces an estate report. See [Assess an estate](/docs/guides/migration/assess-an-estate).

## 2. Plan the order

Sort sites into waves (groups that move together). Start with low-risk sites, and leave the sites with heavy traffic or many integrations for later. The [migration plan template](/docs/institutions/migration-plan-template) gives you columns for this.

## 3. Pilot a few sites

Pick a few sites from different departments. Run the [pilot playbook](/docs/institutions/pilot-playbook) on them before you move the rest.

## 4. Move each site

For each site, run the preflight (the check before a move), read the dossier, then decide the cutover (the move itself). See [Preflight](/docs/guides/migration/preflight) and [Cutover and rollback](/docs/guides/migration/cutover-and-rollback).

The cutover action is not available yet. Check the current status on that page before you schedule a wave.

## 5. Roll out changes

After a site is live, send its updates through the rollout controls. See [Rollout governance](/docs/institutions/rollout-governance).

Mixed estates that include shared hosting need a separate plan. See [Mixed estates and cPanel](/docs/institutions/mixed-estates-and-cpanel).

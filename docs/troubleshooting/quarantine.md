This page explains why a site is quarantined and where to find the problem. It is for site owners.

A site is quarantined after three failures in a row on the same problem. The health view names the problem in its finding.

## What quarantine does

A quarantined site stops accepting changes after repeated failures. It stays that way until a person releases it. A code release or a settings change waits until the site is released.

## How a site leaves quarantine

A person on the Drupflare team releases the quarantine after checking the cause. There is no button for it on the site page in this release.

If you need a quarantined site back, contact [support@drupflare.com](mailto:support@drupflare.com). Include the site name and the request id from the health page. Do not send the owner token or any password.

## Avoid a repeat

Read the finding that started the quarantine. Fix the cause in your site, such as a module or a setting you changed. Then contact support, so the release can be checked against the fix.

See [repair ladder explained](/docs/troubleshooting/repair-ladder-explained) for the steps that come before quarantine.

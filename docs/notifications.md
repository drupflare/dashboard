Drupflare sends transactional email only. Every message names one category. Essential categories always send. Optional categories send only to users who opted in.

There is no category for promotions, announcements or referrals, so the code cannot send one. Feature announcements appear in the changelog banner and page.

## Uncertain messages

A message whose classification is unclear takes the stricter route. It goes to the billing or legal contact by email, appears in the app, and carries no promotional wording.

## Unsubscribe

Each optional message carries a signed unsubscribe link for its own category, and the `List-Unsubscribe` and `List-Unsubscribe-Post` headers point at the same link. A browser that opens it lands on a page that asks for confirmation. A mail client that posts the one-click form switches that one category off. The link changes only the category it names, and using it twice changes nothing. The token expires after 365 days.

The signing key comes from the existing `AUTH_CODE_SECRET` through HKDF with the context `drupflare.unsubscribe.v1`, so no separate secret exists. Where that secret is unset, optional mail waits and essential mail is unaffected.

A person's own choices are stored for each optional category and start off. An organization contact keeps its own notify switch, which is its choice for the same optional mail, and its unsubscribe link turns that switch off. Essential messages carry no unsubscribe link and no list headers, and a preference cannot switch them off.

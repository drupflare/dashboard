# Requests to worker

One row per thing the dashboard needs from `worker`. No request here blocks the dashboard: until a row lands, the dashboard composes the same data from routes that exist in `v1.0.4`. Priorities: Serving blocks managed serving, Feature blocks a named dashboard feature, Workaround removes a workaround.

| #   | Request                                                                                                                                                            | Priority   | Status                                    | Dashboard fallback until it lands                                                                                           |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------- | ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 1   | Cache API guard so a Workers for Platforms user Worker renders. `CACHE_API=off` stops every `caches.default` access.                                               | Serving    | In the worker repository, ships in v1.0.5 | None. A managed Drupal site cannot serve without it.                                                                        |
| 2   | Pre-bundled managed deploy artifact as a second release asset, so the dashboard uploads one file instead of building from source.                                  | Serving    | Open                                      | Build from the release source in a Container.                                                                               |
| 3   | Owner-assertion verification (`owner-assertion` contract): verify the Ed25519 assertion against `DRUPFLARE_ASSERTION_KEY` and keep a seen-id set for its lifetime. | Feature    | Open                                      | Stored owner token, envelope-encrypted, with reveal and rotate behind step-up.                                              |
| 4   | Native `/.well-known/drupflare` (`discovery` contract), generated from `levers.ts`, `capabilities.ts`, `KV_OVERRIDABLE`, `OWNER_ONLY_LEVERS` and `LEVER_DOMAINS`.  | Feature    | Open                                      | The dashboard composes the document from `GET /settings`, `/health`, `/deployment`, `/serve-stats` and the fleet inventory. |
| 5   | Read-only site database route for the `site-db-console` contract, on a read-only connection with row and time limits.                                              | Feature    | Open                                      | No console. The screen stays hidden.                                                                                        |
| 6   | Usage push: the worker posts `usage` reports (hourly intervals) to the dashboard.                                                                                  | Workaround | Open                                      | Poll `/serve-stats` and reconcile against Cloudflare GraphQL.                                                               |
| 7   | Release webhook (`releases` contract) with `schemaVersion` and `acceptsSchema`, posted when a release publishes.                                                   | Feature    | Open                                      | An admin screen registers a release from a manifest URL and checks the sha256.                                              |
| 8   | Streaming `/export` and `/restore` for Adopt and backups, with no full-body buffering.                                                                             | Feature    | Open                                      | None. Adopt and backup export wait for it.                                                                                  |
| 9   | Per-call git token: a token passed on one `git` route call and never stored.                                                                                       | Workaround | Open                                      | Stored token in the repository connection, envelope-encrypted.                                                              |
| 10  | Module census as JSON from the module browser data, with name, version, enabled state and advisory state.                                                          | Workaround | Open                                      | Parse the existing module listing.                                                                                          |

Names in rows 1 and 4 were checked against the worker tree on 2026-11-05: `CACHE_API` appears in `wrangler.managed.jsonc` and `src/ops/cache-api.ts`, and `KV_OVERRIDABLE`, `OWNER_ONLY_LEVERS` and `LEVER_DOMAINS` appear in the worker's lever sources and tests. Every row is re-read against the released tag before the dashboard depends on it.

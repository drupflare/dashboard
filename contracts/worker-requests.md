# Requests to worker

One row per thing the dashboard needs from `worker`. No request here blocks the dashboard: until a row lands, the dashboard composes the same data from routes that exist in `v1.0.4`. Priorities: P0 blocks managed serving, P1 blocks a named dashboard feature, P2 removes a workaround.

| #   | Request                                                                                                                                                            | Priority | Status                                       | Dashboard fallback until it lands                                                                                           |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------- | -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 1   | Cache API guard so a WfP user Worker renders. `CACHE_API=off` stops every `caches.default` access.                                                                 | P0       | Done in the held v1.0.5 patch. Not released. | None. A managed Drupal site cannot serve without it (spike S1).                                                             |
| 2   | Pre-bundled managed deploy artifact as a second release asset, so the dashboard uploads one file instead of building from source.                                  | P0       | Open                                         | Build from the release source in a Container.                                                                               |
| 3   | Owner-assertion verification (`owner-assertion` contract): verify the Ed25519 assertion against `DRUPFLARE_ASSERTION_KEY` and keep a seen-id set for its lifetime. | P1       | Open                                         | Stored owner token, envelope-encrypted, with reveal and rotate behind step-up.                                              |
| 4   | Native `/.well-known/drupflare` (`discovery` contract), generated from `levers.ts`, `capabilities.ts`, `KV_OVERRIDABLE`, `OWNER_ONLY_LEVERS` and `LEVER_DOMAINS`.  | P1       | Open                                         | The dashboard composes the document from `GET /settings`, `/health`, `/deployment`, `/serve-stats` and the fleet inventory. |
| 5   | Read-only site database route for the `site-db-console` contract, on a read-only connection with row and time limits.                                              | P1       | Open                                         | No console. The screen stays hidden.                                                                                        |
| 6   | Usage push: the worker posts `usage` reports (hourly intervals) to the dashboard.                                                                                  | P2       | Open                                         | Poll `/serve-stats` and reconcile against Cloudflare GraphQL.                                                               |
| 7   | Release webhook (`releases` contract) with `schemaVersion` and `acceptsSchema`, posted when a release publishes.                                                   | P1       | Open                                         | An admin screen registers a release from a manifest URL and checks the sha256.                                              |
| 8   | Streaming `/export` and `/restore` for Adopt and backups, with no full-body buffering.                                                                             | P1       | Open                                         | None. Adopt and backup export wait for it.                                                                                  |
| 9   | Per-call git token: a token passed on one `git` route call and never stored.                                                                                       | P2       | Open                                         | Stored token in the repository connection, envelope-encrypted.                                                              |
| 10  | Module census as JSON from the module browser data, with name, version, enabled state and advisory state.                                                          | P2       | Open                                         | Parse the existing module listing.                                                                                          |

Names in rows 1 and 4 were checked against the worker tree on 2026-11-05: `CACHE_API` appears in `wrangler.managed.jsonc` and `src/ops/cache-api.ts`, and `KV_OVERRIDABLE`, `OWNER_ONLY_LEVERS` and `LEVER_DOMAINS` appear in the worker's lever sources and tests. Before P2 a survey agent re-reads every row against the released tag.
